01 / CUSTOMER JOB

사용자는 AI 도구가 아니라
“지금 뜨는 저 영상”을 원한다.

“저 영상, 내 사진으로 만들어서 올리고 싶다.”

현재 사용자는 생성 모델을 알아내고, 각각 가입·결제하고, 프롬프트와 설정을 찾고, 실패를 재시도하고, 편집까지 해야 한다. 유행의 수명은 짧지만 제작 과정은 복잡하다.

지금의 경험

트렌드 발견 → 모델 조사 → 구독 → 프롬프트 탐색 → 생성 실패 → 재생성 → 편집 → 게시

만들려는 경험

템플릿 선택 → 자료 업로드 → 완성본 다운로드

필요한 입력, 예상 시간, 가격과 결과 예시를 처음부터 명확히 보여준다.

가설: 특정 결과를 보고 방문한 사용자는 범용 생성 도구보다 구매 목적이 분명하다. 단, 조회수와 유료 수요는 별도로 검증해야 한다.

02 / POSITIONING

“더 쉬운 AI 도구”만으로는 부족하다.

Higgsfield 등은 이미 트렌딩 템플릿과 사진 업로드 기반 생성을 제공한다. 여러 모델을 한곳에서 쓰거나 프롬프트를 숨기는 기능만으로는 방어력이 약하다.

추천 포지셔닝

“이번 주 뜨는 AI 영상, 내 사진만 넣으면 완성.”

범용 AI 제작 플랫폼이 아니라, 트렌드별 결과물을 판매하는 서비스로 시작한다. 새로운 유행을 빨리 찾아도 품질이 낮으면 의미가 없고, 품질이 좋아도 유행이 지나면 구매 이유가 약해진다.

장기적으로 축적할 자산

  • 발견·출시 속도: 트렌드 감지부터 템플릿 공개까지의 시간.
  • 재현성: 입력 사진·모델·설정별 사용 가능한 결과 비율.
  • 경제성: 완성본 하나를 만드는 데 실제로 드는 총비용.
  • 구매 데이터: 조회가 아닌 구매·다운로드·재구매로 이어지는 트렌드.
가장 큰 사업 위험
재미로 한 번 써보고 끝나는 서비스가 될 수 있다. “다음 유행에도 다시 결제하는가?”가 핵심 검증 질문이다. 반복 게시가 필요한 소규모 크리에이터는 검토할 초기 고객군이다.
03 / AGENT OPERATING SYSTEM

발견보다 중요한 것은
판매 가능한 레시피로 전환하는 일.

트렌드 발견핵심 SNS·선정한 크리에이터·허용된 수집 경로를 통해 후보를 모은다.
후보 점수화최근 반응 증가, 독립 계정 확산, 따라 만들기 욕구와 제작 난도를 평가한다.
레시피 확보·실험공개된 제작 방식과 모델을 확인한다. 없으면 제한된 시간·예산 안에서 실험한다.
재현성 검증다양한 권한 확보 사진으로 테스트하고 품질·비용·실패 유형을 기록한다.
템플릿 상품화예시, 입력 가이드, 가격, 처리 시간, 권리·안전 검토를 포함해 출시한다.
성과 피드백구매·실패·환불·재구매 데이터로 추천과 레시피를 개선하고 낡은 템플릿은 내린다.

템플릿 레시피에 포함할 내용

모델·버전 / 입력 사진 조건 / 전처리 / 프롬프트·설정 / 길이·화면비 / 후처리 / 품질 기준 / 재시도·대체 경로 / 권리 확인 / 비용 상한.

운영 원칙
바이럴 점수와 상품화 점수를 분리한다. 예산 안에서 재현되지 않으면 패스한다. 초기에는 에이전트가 후보를 찾고 사람이 출시를 승인하는 방식이 적절하다. 모든 SNS 자동 순회부터 구축하지 않는다.
04 / UNIT ECONOMICS

이익은 판매가보다
생성 실패 비용에 민감하다.

초기에는 무제한 구독보다 템플릿별 차감량이 다른 생성권 묶음을 권장한다. 고비용 모델·긴 영상·오디오 생성은 별도 차감량을 적용한다.

아래는 실적이 아닌 시뮬레이션

가정: 세전 판매가 $9.99, 5초 완성본 5개, 완성본당 평균 1.5회 생성, 기타 처리비 개당 $0.15. 미국 외 카드 결제에 Lemon Squeezy의 6.5% + $0.50을 적용. 세금이 추가되는 거래는 수수료가 달라질 수 있다.

잔여액은 순이익이 아니다. 광고비·인건비·환불·정산 수수료·추가 인프라 비용·세금 등을 제외하지 않았다. 평균 1.5회 생성은 가정이며, 실제 테스트로 측정해야 한다. 모델 가격과 결제 요율은 변경될 수 있다.

가격·운영 설계

  • 저비용·고성공률 템플릿을 기본 상품으로 구성한다.
  • 고비용 템플릿은 생성권을 더 차감하거나 별도 가격으로 판매한다.
  • 시스템 오류와 “정상 생성됐지만 취향에 안 맞는 결과”의 대응을 구분한다.
  • 무료 무제한 생성 대신 권리를 확보한 완성 예시·저비용 미리보기를 제공한다.
  • 생성권은 서비스 내부 사용권으로 설계하고 환전·양도 가능한 지갑과 구분한다. 결제사 승인은 별도로 확인한다.
05 / PAYMENT & MARKET ENTRY

해외 출시와 MoR를 검토하되,
얼굴 기반 기능의 승인이 선행돼야 한다.

MoR(Merchant of Record)는 고객 거래의 판매 주체가 되어 결제와 거래 관련 세금 처리를 담당하는 구조다. 일반 PG보다 해외 판매의 운영 부담을 줄일 수 있지만, 판매자의 소득 신고나 사업상 의무까지 모두 대체하는 것은 아니다.

우선 문의 후보 · 승인 미확정

Lemon Squeezy

  • 공식 지원 국가에 한국이 포함되어 있다.
  • 스토어 승인 안내는 통상 2~3영업일이며, 지연·거절 가능성이 있다.
  • 기본 수수료는 5% + $0.50. 국제 거래·PayPal·구독 등에 가산 요율이 있다.
  • 결제사에 KYC·KYB 신원 및 사업 검증이 필요하다.
  • 얼굴 기반 생성 서비스와 내부 생성권 상품의 승인 여부는 실제 샘플을 제출해 확인해야 한다.

현 단계 결론: 가장 먼저 사전 검토할 후보이며, 이 서비스가 승인된다는 보장은 없다.

다른 경로의 주의점

경로검토 결과
Paddle사람 얼굴 생성 관련 제한 카테고리 및 얼굴 교체·딥페이크 관련 항목이 존재한다. 본인 사진이라는 이유만으로 허용을 전제할 수 없다.
Polar금지 목록에 face swaps / deep fakes를 가능하게 하는 콘텐츠 생성이 명시되어 있다. 해당 기능 중심이라면 우선 선택지로 부적절하다.
FreemiusAI 소프트웨어는 지원하지만 딥페이크·무단 얼굴 교체·사칭 등의 금지 조항이 있다. 자동으로 안전한 대안은 아니다.
Stripe 직접 가입현재 직접 가입 지원 국가 목록에 한국이 없다. 해외 법인 경로는 가능하지만 초기 검증을 위해 바로 법인 설립을 권하지는 않는다.
국내 PG국내 사용자 결제 편의에는 강점이 있다. 사업자 등록·심사·사이트 판매자 정보 표시 등을 고려해야 한다. 연동 도구를 쓰더라도 이러한 의무가 사라지지 않는다.

승인 전 확인 체크리스트

  1. 기능을 정확히 구분한다: 사진 애니메이션화 / 인물 변환 / 기존 영상 얼굴 교체.
  2. 실제 샘플, 업로드 권한 확인, 필터·신고·삭제 절차를 제출한다.
  3. 생성권 판매 방식, 가격, 환불·재생성 정책을 설명한다.
  4. 결제창·이메일 영수증·PDF 인보이스·고객 포털·명세 표시를 확인한다.
  5. 승인 후 소액 실결제와 환불로 전체 경로를 검증한다.

현재는 공개 정책을 조사한 단계다. 결제사 문의·계정 승인·실결제 검증은 수행되지 않았다. 국가별 소비자·개인정보·사업자 표시 의무는 별도로 확인해야 한다.

06 / TRUST & SAFETY

안전장치는 나중에 붙이는 기능이 아니다.

콘텐츠·인물 권리

본인 또는 명시적 사용 권한이 있는 자료만 허용한다. 사칭·비동의 합성·성인 콘텐츠를 금지하고, 미성년자 입력 등 고위험 범위는 초기 출시에서 제외하는 방안을 권장한다.

원본 영상·음악·캐릭터

유행의 연출을 참고하는 것과 원본을 재사용하는 것은 다르다. 상업 이용권을 확인하고 템플릿별 권리 이력을 남긴다.

개인정보와 보관

얼굴 사진은 민감도가 높은 개인정보다. 최소 수집·보관, 삭제 기능, 모델 제공사 전송·보관 안내와 접근 통제를 설계한다.

플랫폼·모델 정책

허용된 수집 경로, 모델별 상업 이용·출력 정책, SNS의 AI 생성 표시 요구를 확인한다. 게시 성과나 바이럴을 보장하지 않는다.

07 / LEAN VALIDATION

전체 자동화보다
작은 유료 수요를 먼저 확인한다.

권장 MVP 범위

  • 영어권의 좁은 고객군을 대상으로 한 웹 서비스.
  • 권리·안전·재현성을 검토한 템플릿 3~5개.
  • 예시 확인 → 자료 업로드 → 생성권 결제 → 작업 상태 확인 → 다운로드.
  • 한두 개의 모델 제공 경로와 제한된 재시도 정책.
  • 트렌드 수집은 반자동, 템플릿 출시는 사람 승인.
  1. 샘플 검증
    다양한 권한 확보 사진으로 품질·입력 가이드·실패 유형·실제 원가를 측정한다.
  2. 결제사 사전 검토
    MVP 샘플로 취급 가능 여부를 확인한다. 제품 개발과 병행하되 승인 전 유료 판매는 시작하지 않는다.
  3. 소규모 유료 출시
    허가된 예시와 협업 크리에이터 콘텐츠로 유입을 만들고 실제 구매를 확인한다.
  4. 다음 유행에서 반복 검증
    신규 템플릿을 출시해 기존 구매자가 다시 결제하는지 측정한다.
  5. 검증된 구간부터 자동화
    구매·품질·원가가 좋은 유형만 자동화하고, 실패가 많은 유형은 제거하거나 가격을 조정한다.

함께 볼 지표

유료 전환율 / 첫 결과 사용 가능 비율 / 완성본당 실제 원가 / 환불률 / 발견부터 출시까지의 시간 / 다음 트렌드에서 재구매율.

판단 원칙
높은 조회수만으로 확대하지 않는다. 구매가 없으면 포지셔닝·고객군을 다시 보고, 구매는 있지만 실패 비용이 높으면 레시피·가격을 먼저 바꾼다. 실측 전 예상 매출이나 시장 점유율을 확정하지 않는다.
08 / COFOUNDER DISCUSSION

공동창업 전에 함께 결정할 것.

  1. 첫 고객: 재미를 원하는 일반 사용자인가, 반복 게시가 필요한 소규모 크리에이터인가?
  2. 첫 템플릿 범위: 어떤 유형을 빠르고 안정적으로 재현할 수 있는가?
  3. 얼굴 기능의 범위: 사진 애니메이션과 얼굴 교체를 어디까지 포함할 것인가? 결제사가 허용하는가?
  4. 역할 분담: 제품·생성 인프라 / 트렌드 탐색·레시피 / 크리에이터 협업·유입 / 결제·고객 대응은 누가 맡는가?
  5. 검증 예산·중단 기준: 생성 실험과 고객 획득에 얼마를 쓰고 어떤 결과이면 계속할 것인가?
  6. 운영 책임: 템플릿 출시 승인과 품질·권리·개인정보 사고 대응의 책임자는 누구인가?
